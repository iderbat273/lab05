## 2. Лабораторийн ажлын зорилго

Энэхүү лабораторийн ажлын зорилго нь Postman болон Newman ашиглан курсийн бүртгэлийн REST API-д системийн тест хийх юм. Бүртгэл үүсгэдэг `POST /registrations` endpoint-ийг тестлэх үндсэн систем (SUT) болгон сонгосон.

Тестээр амжилттай бүртгэл үүсэх, оюутан байхгүй байх, оюутны төлөв идэвхгүй байх, хичээл байхгүй байх, урьдчилсан нөхцөл хангагдаагүй байх, хүсэлтийн шаардлагатай талбар дутуу байх зэрэг тохиолдлуудыг шалгасан. Мөн олон алдаа зэрэг тохиолдсон үед API аль алдааг түрүүлж шалгаж байгааг туршсан.

Postman collection дотор `baseUrl` нэртэй хувьсагч үүсгэж, утгыг `http://localhost:3000` гэж тохируулсан. Ингэснээр collection нь серверийн хаягаа өөртөө агуулж, Newman-аар ажиллахдаа тусдаа environment хувьсагч шаардахгүй.

## 3. Тестийн загварчлал

Тест боловсруулахдаа дараах таван алхмыг ашигласан.

1. **Тестлэх функцийг сонгох:** Бүртгэл үүсгэдэг `POST /registrations` endpoint.
2. **Оролтын сонголтуудыг тодорхойлох:** Оюутан байгаа эсэх, оюутны төлөв, хичээл байгаа эсэх, урьдчилсан нөхцөл болон хүсэлтийн талбарууд.
3. **Төлөөлөх утгуудыг сонгох:** Идэвхтэй болон идэвхгүй оюутан, байгаа болон байхгүй хичээл, урьдчилсан нөхцөл хангасан болон хангаагүй утгууд.
4. **Хүлээгдэж буй үр дүнг тодорхойлох:** HTTP төлөвийн код, `result` талбар болон шаардлагатай хариуны талбарууд.
5. **Тестийн тохиолдлууд боловсруулах:** Сонгосон нөхцөлүүдийг хамарсан 10 тестийг collection-д нэмсэн.

### 3.1. Сонгосон утгууд ба зорилго

| Шалгах нөхцөл | Төлөөлөх утга | Шалгах зорилго |
|---|---|---|
| Оюутан байгаа эсэх | Байгаа болон байхгүй оюутан | Оюутан олдох эсэх |
| Оюутны төлөв | `active`, `inactive` | Идэвхтэй эсэхийг шалгах |
| Хичээл байгаа эсэх | Байгаа болон байхгүй хичээл | Хичээл олдох эсэх |
| Урьдчилсан нөхцөл | Хангасан, хангаагүй, шаардлагагүй | Урьдчилсан хичээлийн шалгалт |
| Шаардлагатай талбар | `studentID`, `courseID` | Дутуу талбарт өгөх хариу |
| Олон алдаа давхцах | Байхгүй оюутан + байхгүй хичээл | Алдаа шалгах дараалал |
| Олон алдаа давхцах | Идэвхгүй оюутан + байхгүй хичээл | Оюутны төлөвийн шалгалтын дараалал |
| Амжилттай бүртгэл | HTTP `201`, `OK` | Бүртгэл үүссэн эсэх |
| Алдааны хариу | HTTP төлөв ба `result` код | Алдааг зөв буцааж байгаа эсэх |

Амжилттай бүртгэлийн `registrationID` нь бүртгэл бүрд өөр байж болох тул тодорхой утгатай тэнцүү гэж шалгаагүй. Харин талбар байгаа эсэх болон шаардлагатай төрлийг шалгасан.

## 4. Тестийн тохиолдлууд ба хүлээгдэж буй үр дүн

| № | Тестийн нөхцөл | Хүлээгдэж буй HTTP код | Хүлээгдэж буй үр дүн |
|---:|---|---:|---|
| 1 | Идэвхтэй оюутан, хичээлийн урьдчилсан нөхцөл хангагдсан | 201 | `OK` |
| 2 | Оюутан байхгүй | 200 | `ERROR_NO_STUDENT` |
| 3 | Оюутан идэвхгүй | 200 | `ERROR_INACTIVE_STUDENT` |
| 4 | Хичээл байхгүй | 200 | `ERROR_NO_COURSE` |
| 5 | Урьдчилсан нөхцөл хангагдаагүй | 200 | `ERROR_PREREQUISITES` |
| 6 | Оюутан болон хичээл хоёулаа байхгүй | 200 | `ERROR_NO_STUDENT` |
| 7 | Оюутан идэвхгүй, хичээл байхгүй | 200 | `ERROR_INACTIVE_STUDENT` |
| 8 | Урьдчилсан нөхцөл шаардахгүй хичээлд бүртгүүлэх | 201 | `OK` |
| 9 | `studentID` талбар дутуу | 400 | `ERROR_BAD_REQUEST` |
| 10 | `courseID` талбар дутуу | 400 | `ERROR_BAD_REQUEST` |

Тест бүр шаардлагатай оюутан, хичээлийн тохиргоог өөрөө хийж, дараа нь бүртгэлийн хүсэлт илгээдэг. Ингэснээр тестүүд өмнөх тестийн өгөгдлөөс хамаарахгүй ажиллах боломжтой.

Олон алдаа давхцсан 6 болон 7-р тестээр API-ийн алдаа шалгах дарааллыг шалгасан. Энэ нь нэг хүсэлтэд хэд хэдэн нөхцөл буруу үед API ямар алдааг түрүүлж буцааж байгааг харуулна.

## 5. Newman тестийн үр дүн

Тестийн үр дүнг `results/` хавтсанд хадгалсан.

### 5.1. PASS — Бүх тест амжилттай

- **Файл:** `results/newman-pass.txt`
- **Хүлээгдэж буй үр дүн:** Бүх тест амжилттай.
- **Failed:** 0
- **Exit code:** 0

PASS ажиллуулалтаар API хүлээгдэж буй үр дүнг буцааж байгааг шалгасан. Newman-ийн `exit code 0` нь collection-д алдаатай assertion гараагүйг илэрхийлнэ.

### 5.2. FAIL — Зориудаар алдаа оруулсан тест

- **Файл:** `results/newman-fail.txt`
- **Хүлээгдэж буй үр дүн:** Дор хаяж нэг assertion амжилтгүй болох.
- **Failed:** 1
- **Exit code:** 1

FAIL collection нь үндсэн collection-ийн хуулбар бөгөөд нэг oracle буюу хүлээгдэж буй үр дүнгийн шалгалтыг зориудаар буруу болгосон. Энэ нь Newman тестийн алдааг илрүүлж, амжилтгүй exit code буцаадаг эсэхийг шалгана. Үндсэн collection-ийн шалгалтыг зориудаар өөрчлөөгүй.

### 5.3. DOWN — Сервер ажиллахгүй үеийн тест

- **Файл:** `results/newman-down.txt`
- **Хүлээгдэж буй үр дүн:** Серверт холбогдож чадахгүй байх.
- **Алдаа:** `ECONNREFUSED`
- **Exit code:** 1

DOWN тестийг серверийг зогсоосны дараа ажиллуулсан. Серверээс хариу ирээгүй тул Newman холболтын алдаа бүртгэж, ажиллуулалт амжилтгүй болсон.

Энэ нь API бизнес логикийн буруу үр дүн буцаасантай адил биш. Сервер ажиллахгүй эсвэл холболт боломжгүй үед тест хүсэлтээ амжилттай гүйцэтгэж чадахгүй байгааг илэрхийлнэ.

### 5.4. Exit code-ийн тайлбар

| Төлөв | Exit code | Тайлбар |
|---|---:|---|
| PASS | 0 | Assertion-ууд амжилттай |
| FAIL | 1 | Дор хаяж нэг assertion амжилтгүй |
| DOWN | 1 | Серверт холбогдож чадаагүй |

`results/newman-pass-exit.txt`, `results/newman-fail-exit.txt`, `results/newman-down-exit.txt` файлуудад харгалзах ажиллуулалтын exit code-ийг хадгалсан.

## 7. Тест ажиллуулах заавар

### 7.1. Серверийг ажиллуулах

Төслийн хавтас дотроос:

```bash
cd ~/lab05
node server.js
```

Сервер ажиллаж байх үед өөр terminal нээнэ.

### 7.2. PASS collection ажиллуулах

```bash
cd ~/lab05
newman run lab05-collection.json | tee results/newman-pass.txt
```

Exit code-ийг хадгалахдаа:

```bash
newman run lab05-collection.json
echo "exit=$?" | tee results/newman-pass-exit.txt
```

### 7.3. FAIL collection ажиллуулах

Сервер ажиллаж байгаа үед:

```bash
cd ~/lab05
newman run lab05-collection-fail.json | tee results/newman-fail.txt
```

Exit code-ийг хадгалахдаа:

```bash
newman run lab05-collection-fail.json
echo "exit=$?" | tee results/newman-fail-exit.txt
```

### 7.4. DOWN тест ажиллуулах

Эхлээд серверийг ажиллуулж байгаа terminal дээр `Ctrl+C` дарж серверийг зогсооно. Дараа нь өөр terminal дээр:

```bash
cd ~/lab05
newman run lab05-collection.json 2>&1 | tee results/newman-down.txt
echo "exit=${PIPESTATUS[0]}" | tee results/newman-down-exit.txt
```

Энэ команд нь Bash shell-д зориулагдсан. `PIPESTATUS[0]` нь `tee`-ийн биш, Newman-ийн exit code-ийг авна.

**Анхаарах зүйл:** Дээрх командуудыг дахин ажиллуулбал үр дүнгийн файлуудын өмнөх агуулга шинэ үр дүнгээр солигдоно. Тайланд бичсэн тоонууд бодитоор хадгалсан логтой таарч байгаа эсэхийг шалгах хэрэгтэй.

## 8. Git хувилбарын удирдлага

Лабораторийн ажлын явцад файлуудыг үе шаттайгаар Git-д commit хийсэн. Үүнд төслийн эхлэл, API сервер, үндсэн тестүүд, зориудаар алдаа оруулсан collection, Newman-ийн үр дүн болон тайлангийн өөрчлөлтүүд орно.

Commit-ийн түүхийг дараах командаар шалгаж болно:

```bash
git log --oneline
```

Git-д ороогүй өөрчлөлт байгаа эсэхийг:

```bash
git status --short
```

командаар шалгана.

## 9. Дүгнэлт

Энэ лабораторийн ажлаар Postman collection болон Newman ашиглан REST API-ийн системийн тест боловсруулж ажиллууллаа. Тестийн загварчлалын таван алхмыг ашиглан шалгах нөхцөл, төлөөлөх утга, хүлээгдэж буй үр дүн болон тестийн тохиолдлуудыг тодорхойлсон. Амжилттай бүртгэл үүсэх болон хэд хэдэн төрлийн алдааны хариуг шалгасан. Олон алдаа давхцсан үед API аль алдааг түрүүлж шалгаж байгааг мөн туршсан. Үндсэн collection-д `baseUrl` хувьсагч тохируулж, Newman-аар ажиллуулах боломж бүрдүүлсэн. PASS ажиллуулалт нь тестүүд хүлээгдэж буй үр дүнтэй таарч байгааг шалгасан. FAIL хувилбарт нэг шалгалтыг зориудаар буруу болгож, Newman алдааг илрүүлж байгааг баталсан. DOWN хувилбарт сервер ажиллахгүй үед холболтын алдаа гарч, тест амжилтгүй болдгийг ажигласан. Тестийн лог болон exit code-ийг хадгалснаар үр дүнг дахин шалгах боломжтой болгосон. Энэ ажлаар API-ийн зөв ажиллагаа, алдааны боловсруулалт болон автомат тестийн үр дүнг тайлбарлах дадлага эзэмшсэн.
